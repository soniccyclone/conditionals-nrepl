#+TITLE: 3. Architecture options and trade-offs
#+OPTIONS: ^:nil toc:2

Four shapes were drafted independently and scored. The panel was cut short for budget; scoring below is the planner's synthesis of the audit, prior art and the drafts' briefs, not the judges' numeric output.

* The options
** A. Inline conditionals everywhere
Rename every file to =.cljc=, wrap each of the 1 089 host sites in =#?(:clj … :cljr …)=.
- Pro: no new namespaces, one file per concern, nothing to explain upstream.
- Con: =transport.clj= (54 sites), =tls.clj= (60), =completion.clj= (78), =cmdline.clj= (61) become unreadable; type hints cannot be conditionalized inline (=^Writer=) so hints need =^{:tag #?(…)}= or =#?@= splices; every JVM diff touches the CLR branch; reviewers must know .NET to review nREPL.
- Verdict: =NOGO= for the heavy files; fine for ≤ ~12-site files (15 files in the audit).
** B. Host seams: =.cljc= core + =nrepl.host.*= per platform  (recommended base)
Shared =.cljc= files call a small set of host namespaces. Each seam is a =.cljc= façade whose =ns= =:require= is conditional:
#+BEGIN_SRC clojure
(ns nrepl.host.threading
  (:require #?(:clj [nrepl.host.jvm.threading :as impl]
               :cljr [nrepl.host.clr.threading :as impl])))
(def run-thread! impl/run-thread!)   ; background thread, named, returns {:thread :cancel!}
(def interrupt! impl/interrupt!)
(def schedule-once! impl/schedule-once!)
(def make-queue impl/make-queue)      ; blocking FIFO with put/take/poll-ms
(def make-rendezvous impl/make-rendezvous) ; SynchronousQueue shape
#+END_SRC
Seams the audit justifies: =threading= (executors, interrupt, queues), =io= (streams, pushback, utf8, readers, writers, quota, tee), =net= (listen/accept/connect, unix, connection record), =tls= (PEM → context, wrap stream), =reflect= (members, classpath/assembly scan, keyword table), =process= (exit, at-exit, signals, block-forever), =env= (home, getenv, path, file-exists?, read-edn), =runtime= (host name/version, uuid, resource, can-stop-threads?).
- Pro: JVM impl namespaces are moved code, zero behaviour change, reviewable per seam; CLR files never load on JVM; a CLJS/jank port adds a third impl dir, nothing else; kondo/cljfmt see only =.cljc=/=.clj=.
- Con: ~8 new namespaces and a protocol-ish API to keep stable; two-hop indirection in hot paths (bencode byte reads: use =definline=/direct fns, not protocols); upstream must accept "seams for a platform we don't ship".
** C. Kernel/host purist (babashka.nrepl shape)
Pure =.cljc= kernel (codec over abstract byte source, middleware linearization, session state as data, ops) with a =Host= record injected at =start-server=.
- Pro: cleanest for a third dialect; kernel testable with fake hosts.
- Con: large JVM rewrite (session executor, transport loop, print writers are all host-shaped today); performance of record-dispatch in the byte codec; upstream would read it as a different project. Prior art: =clr.tools.nrepl= top level is this shape and still lacks interrupt, stdin, sessions parity.
- Verdict: =DEFERRED=; B converges toward C seam by seam without the rewrite.
** D. ClojureCLR =.cljr= override files
Keep =.cljc= with sparse =#?=; for heavy namespaces ship =nrepl/util/threading.cljr=, =nrepl/socket.cljr=, =nrepl/tls.cljr=, =nrepl/util/out.cljr= beside the =.cljc=; CLR loads the =.cljr=, JVM never sees it (=RT.cs:3585=).
- Pro: zero JVM diff for those files; no seam API design; fastest to a Godot prototype.
- Con: duplicated whole namespaces drift from upstream on every sync; =clj-kondo= has no =:cljr= language (lints =.cljr= as default or skips), =cljfmt= default pattern excludes =.cljr=, kaocha ignores them; upstream would hold untested files; a =.cljr= file cannot use =#?= at all.
- Verdict: use *only* as a bridge for =tls= and =cmdline= where the CLR version is a subset, and only under =src/cljr/= as a separate root, never beside the =.cljc=.
** E. C# support assembly for the Java classes
Replace =src/java/nrepl/**= with =src/csharp/nrepl/**= (=TextReader=/=TextWriter= subclasses, pushback stream, thread factory) compiled by the Godot =.csproj= or a packager project.
- Pro: ~150 lines of C# replaces 438 lines of Java 1:1; no =proxy= overhead; =Godot= already builds C#.
- Con: ties the CLR library to a C# build step and to =Clojure.dll= if =IFn= is referenced; NuGet packaging of mixed C#+cljc needs the packager csproj anyway. ClojureCLR =proxy= over abstract =TextWriter= works (prior art =cnrepl/print.clj:79=) but every call is reflective.
- Verdict: =DECIDE= D5. Default: pure-Clojure =proxy= first (no build step), C# later if profiling says so.

* Recommended synthesis
1. B as the base. Seams first, on the JVM, as pure moves (PRs 1–5 in the roadmap). Each PR leaves the JVM suite green and is upstream-shaped.
2. Rename =.clj= → =.cljc= file by file after its seam lands (git keeps rename history; kondo/cljfmt unaffected).
3. CLR implementations under =src/clojure/nrepl/host/clr/*.cljr= (plain CLR code, no =#?=), never loaded on JVM. Java-class replacements as =proxy= in =nrepl.host.clr.io=; revisit E after profiling.
4. D only for =cmdline= (CLR entry is a subset) and as a temporary bridge for =tls= if the =SslStream= port slips.
5. Godot integration lives outside the library: a =GodotNreplHost= Node (C#) that sets load path, boots =clojure.lang.RT=, calls =nrepl.server/start-server= with a Godot =:exec-fn= dispatcher, and stops it in =_ExitTree=. The library exposes the hooks (=:exec-fn=, =:thread-factory=, =:at-exit=); the Node is a separate repo or =examples/godot=.

* Dialect extensibility (not planned, must not be precluded)
| Dialect | What B gives for free | What it would add |
|---+---+---|
| CLJS (self-hosted / node) | kernel =.cljc=, middleware graph, bencode codec over byte abstraction | =nrepl.host.cljs.*= (node net/streams), async eval model (no threads: =:exec= becomes a promise chain), =:cljs= branches in =#?= |
| jank | same kernel if jank reads =.cljc= with its own feature key (=:jank=, unverified) | native host seams; interrupt via signals; C++ interop for sockets |
Rule to keep the door open: seams expose values and fns, never host types, in their =.cljc= signatures; the connection record carries =:in=/=:out= as opaque handles consumed only by the same host's seam.
