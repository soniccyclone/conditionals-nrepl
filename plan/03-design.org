This is the specification an implementer follows. Every seam function has a signature, a JVM body (today's code, moved) and a CLR body (the .NET API it wraps). Claim ids such as =TH6= or =C2= point at [[file:verify/claims.org][verify/claims.org]]; their evidence is in [[file:verify/results.org][verify/results.org]]. Line numbers are those of commit =d00d171= (=df1ed8a= adds only =plan/= files). Second revision: incorporates the verification run, a Sonnet dry run of slice 4, and four reviews (maintainer lens, CLR API, test impact, interop coverage). Third revision: Nathan's decisions of 2026-10-11 (one thread per task, a C# helper assembly, a pure-Clojure error abstraction); nothing here is shaped for upstream, this is a heavily modified fork.

* Shape
One source tree, two load paths.
- Shared files are =.cljc=. A shared file never names a host type; it calls a seam, or uses one of the inline =#?= forms listed in [[Inline sites in shared files]].
- A seam is the *existing* namespace where one exists (=nrepl.util.threading=, =nrepl.util.out=), or a new =nrepl.util.*= namespace (=nrepl.util.io=, =nrepl.util.reflect=, =nrepl.util.runtime=). The seam file is =.cljc=; its =ns= form requires the host implementation conditionally and re-exports it. Implementations live beside it: =nrepl.util.threading.jvm= (=threading/jvm.clj=) and =nrepl.util.threading.clr= (=threading/clr.cljr=). No parallel =nrepl.host.*= tree.
- Two namespaces share nothing between hosts and are not seamed: =nrepl.socket= and =nrepl.tls= stay =.clj= untouched, and the CLR load path carries =nrepl/socket.cljr= and =nrepl/tls.cljr= that define the same public functions (ClojureCLR loads =.cljr= before =.clj=, =A3=; the JVM never reads a =.cljr=). Shared code calls only the contract table below, so either file suffices.
- =nrepl.cmdline= stays =.clj=. Its pure half (option parsing, help text, =server-opts=, URL helpers) is extracted into =nrepl.cmdline.options= (=.cljc=); the CLR gets a server-only =nrepl/cmdline.cljr= entry on top of it (D17).
- Every seam namespace carries ={:no-doc true}= and a docstring "internal host seam". Shared code only calls what the tables below list.

Mechanics an implementer must know (all verified):
- A façade =(def f impl/f)= copies the value: the façade var has none of the impl var's metadata, =definline= inlining is lost through it, and =with-redefs= on the impl var is invisible through the façade. Therefore: hot byte primitives stay inline in =nrepl.bencode= (see the io seam), macros that must expand differently per host live in the =.cljc= façade with =#?= inside the macro body, and tests redefine impl vars by their impl namespace.
- Inline conditional type hints work on both hosts: =[^#?(:clj Thread :cljr System.Threading.Thread) t]= and =#?(:clj ^Thread t :cljr t)= (=L6=, =L5=, =L7=). A hint naming a host type that does not exist is a hard compile error on the CLR (=L3=), and =^{:tag #?(:clj Character :cljr Char)}= on a fn parameter fails because =Char= is a value type (=L7=): drop such hints.
- A reader conditional in operator position, =(#?(:clj .read :cljr .ReadByte) x)=, works on both hosts, including inside a =definline= body (=L1=). The =Foo.= constructor sugar cannot hold =#?=; write =(new #?(:clj EOFException :cljr System.IO.EndOfStreamException) msg)=.
- On ClojureCLR only the =System= namespace is auto-imported (=L2=, =L6=): =Thread=, =ThreadStart=, =Integer=, =Long=, =Character=, =Class=, =Iterable=, =Arrays=, =Semaphore= and every =java.*= name resolve to nothing. =Integer/parseInt=, =Long/MAX_VALUE=, =Character/isUpperCase= are compile errors; =Math/…=, =String/valueOf= compile and fail at runtime.
- A call to a missing member on a hinted receiver (=(.getMessage ^Exception e)=, =(.ready r)=, =(.write ^TextWriter w s)=) compiles with a reflection warning and throws =MissingMethodException= at runtime (=B2=, =E9=, =L5=). Loading a namespace proves little; CLR CI must execute the code and treat reflection warnings in =nrepl.*= as errors.
- A =#?(:cljr nil)= stub does not neutralize a later interop call on the stubbed value: =(let [p nil] (.load p x))= is a compile error on the CLR (=L3=). Gate the call, not just the value.
- Every thread the CLR impl creates runs its body under an outermost =(try (f) (catch Exception e (misc/log e …)))= with no rethrow: an uncaught exception on any managed thread, foreground or background, terminates the process (=TH13=).
- =by-ref= out-parameters work only on a statically resolved call with a local whose static type is exactly the parameter type, and not inside a non-tail =try= (=C8=, =TH= extra); seam wrappers that need =TryTake=, =TryParse= are top-level =defn=s with hinted parameters.
- Combine enum flags with =enum-or=, never =bit-or= (=A7=, =B11=).
- Long to Int32 narrowing is checked: =Int64/MaxValue= as a millisecond argument throws =ArgumentException= at the call site (=C8=); clamp inside the seam.
- =(str true)= is ="True"= on the CLR, =(str 1.0)= is ="1"= (=L8=); shared code that stringifies booleans for the wire coerces them explicitly.
- =random-uuid= and =parse-long= are Clojure 1.11; nREPL supports 1.10, so they are not portable replacements (=L2= refuter). Use one-line =#?= forms.

Why this shape and not the others is scored in [[file:05-decisions.org][05-decisions]] D11 (decided).

*** Interrupt policy (D3, decided: forced stop is primary)
The CLR mirrors the JVM =interrupt-stop= exactly; only the kill primitive differs. .NET 8 ships =System.Runtime.ControlledExecution.Run= (=TH5=, =TH6=): it aborts the thread at its next safe point, which includes the back-edge of a tight =loop/recur= (16–18 ms after =Cancel= for every loop shape tested), runs =finally= blocks, surfaces =OperationCanceledException= to the caller of =Run=, and leaves the runtime usable afterwards. Inside the aborted body a user =(catch Exception …)= handler runs but cannot swallow the abort; the abort is re-raised when the handler exits. Because =Run= wraps the body rather than targeting a thread, every exec runs through =run-interruptible= on the session thread, and the reaper is the only caller of =Cancel=.

What the kill cannot do, stated as .NET facts (=TH7=): it does not reach a thread inside a wait (=Sleep=, =Monitor.Wait=, a queue =Take=) or a native call until that call returns, which is why the reaper re-interrupts first (=Interrupt= wakes every wait, =TH1=); it is deferred while the thread is inside a =catch= block and never delivered to a loop that stays inside a =catch= or =finally=; =Cancel= blocks its caller until delivery, so an undeliverable abort parks the reaper thread too (two zombies, R2). The same limits apply to =Thread.stop= on the JVM.

Behaviour on a successful kill is unchanged from the JVM: the =:interrupt= fn CASes =:running= to nil, calls =interrupt-stop=, and =reset-state= starts a fresh session thread and queue (~session.clj:239-252~); the killed thread's =caught= hook sees =stop-exception?= and sends nothing; =run-interruptible= swallows the =Run= exception so the session loop's =(catch Exception …)= never runs =reset-state= a second time (CLR review blocker 1); the loop's CAS then fails and the thread exits. The client gets =:interrupted :done= from the interrupt reply.

Opt-out only: =(:force-interrupt config true)=, read by =interrupt-stop= on both hosts; when false it interrupts and does not schedule the kill. Documented next to =:enable-jvmti-agent= in =doc/modules/ROOT/pages/usage/server.adoc= and in the =interrupt= op docstring. =describe= gains =:aux {:host {:name "jvm"|"clr" :can-stop-threads bool}}= (D13).

The verified proxy fallback for the stdin reader (=C1=, =E5=, =E9=, CLR review):
#+begin_src clojure
(proxy [System.IO.TextReader] []
  (Peek [] (int (poll-char)))                 ; non-blocking, from the queue; never -1 while data is queued
  (Read ([] (int (read-char)))               ; -1 at EOF; LineNumberingTextReader only ever calls this and Peek
        ([buf off len]                        ; one multi-arity clause: proxy dispatches by name, two clauses fail
         (if (zero? (int len)) (int 0)
             (let [c (read-char)] (if (neg? c) (int 0) (do (aset-char buf (int off) (char c)) … (int n)))))))
  (Dispose [disposing] (clear-queue!)))
#+end_src
=read-char= takes from a =BlockingCollection<string>= with a private EOF sentinel compared by =identical?=, sends =need-input= when empty, and on =ThreadInterruptedException= re-interrupts the current thread and returns -1, as =QueuePollingReader.java:61-65= does. Every int-returning method returns =(int …)=: a long throws =InvalidCastException=, nil throws =NullReferenceException=. The =Read(Span<char>)= override the proxy generates throws =InvalidProgramException= if called; nothing in nREPL or ClojureCLR calls it.

The verified proxy fallback for the callback writer (=C2=, =E10=, CLR review):
#+begin_src clojure
(proxy [System.IO.TextWriter] []
  (get_Encoding [] System.Text.Encoding/UTF8)
  (Write ([x] (cond (string? x) (write-str this x)          ; one clause receives Char, String, Char[], Int64, StringBuilder ...
                    (char? x) (write-char this x)
                    (instance? |System.Char[]| x) (write-str this (String. ^chars x))
                    :else (write-str this (str x))))
         ([a b c] (if (string? a) (write-str this (String/Format a b c))   ; (string format, object, object) shares arity 3
                      (write-str this (String. ^chars a (int b) (int c))))))
  (Flush [] …) (Dispose [disposing] (flush!) …) (ToString [] …))
#+end_src
Every body runs under =locking= on a private object (the JVM chain is thread-safe; a proxy is not). Never use =proxy-super= for =Write=: it unmaps every =Write= overload for the duration and the base re-dispatch silently drops text (the prior-art writer has this bug). =WriteLine= arrives as =Write(string)= then =Write(newline)=. Measured cost ~15 ns per =Write(char)= for the proxy versus ~4 ns for the C# class (=C3=); the C# class is the decision (D5).

* Errors (D6)
Every error nREPL itself raises is a pure Clojure =ex-info= with a =:nrepl/kind= keyword and a message written for a human; shared code never constructs or catches a host exception class. The kinds: =::disconnected= (the transport lost its peer), =::listener-closed= (accept after =stop-server=), =::eof= (a message ended early), =::quota-exceeded= (print quota), =::tls-unsupported=, =::stopped= (a forced stop), =::invalid-message= (bencode top level is not a map). The host seams are where native exceptions are mapped: =socket/disconnected?=, =socket/closed-exception?=, the bencode EOF constructors, =threading/stop-exception?= and =io/print-with-quota= each recognise their host's exception and rethrow or return the kind. =safe-handle= reports =(ex-message e)= and, when present, =(:nrepl/kind (ex-data e))= as =:ex-kind=.

User exceptions escaping =eval= keep the host's own class name in =:ex= / =:root-ex=, because they are the user's exceptions and =(str (class e))= already gives the host spelling (=B6=); the reply also carries =:ex-kind= (=:eval-error=, =:read-error=, =:print-error=, =:stopped=) so a client never has to parse the name.
