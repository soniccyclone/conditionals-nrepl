Extra findings:
- AOT route for .NET 8 exists but only via a net9+ build step: the same Clojure.Main 1.12.6 package installed with `dotnet tool install Clojure.Main --version 1.12.6 --framework net9.0 --tool-path <dir>` (after dotnet-install.sh --runtime dotnet --channel 9.0) compiles `foo.e.cljc.dll`, and the net8.0 tool loads that DLL (it references System.Private.CoreLib 9.0.0.0 and Clojure 1.12.6.0). Script: exp/A/a5net9/net9b.sh. Only a trivial namespace was tried.
- nrepl 1.8.0's load-file middleware (src/clojure/nrepl/middleware/load_file.clj) no longer calls Compiler/load; it rewrites the message into an eval with ::eval/bindings = {Compiler/METHOD nil, LOCAL_ENV nil, LOOP_LOCALS nil, NEXT_LOCAL_NUM 0, ...} and :file file-path, and interruptible-eval reads with {:read-cond :allow}. So roadmap slice 14 / 04 §4.6 'Compiler/load 4-arg form' is stale: the CLR port needs (a) the NonPublic Var lookup for those three keys (A7) and (b) nothing else, since read+:read-cond already works (A9). Compiler/load matters only if the old idiom is reintroduced.
- Load-path precedence: BaseDirectory, BaseDirectory/bin, CWD, Clojure.dll dir and entry-assembly dir are probed BEFORE CLOJURE_LOAD_PATH entries (RT.cs:3752-3769), so a namespace file under the CWD shadows one on the env var; ';' is not split on Linux.
- `(bit-or Enum/A Enum/B)` yields a long on ClojureCLR; passing it to a statically resolved interop call (literal type as target) throws InvalidCastException, while a dynamically dispatched call converts it. `enum-or` exists in core and works in both cases. Relevant to every BindingFlags site in the planned reflect/host namespaces.
- Harness trap: `push-thread-bindings` executed as its own top-level form in a -i/-e script is popped by Compiler.eval's finally (Compiler.cs:1259-1285) and invisible to the next form (reproduced with #'*print-length* too); tests must push/pop within one form or use with-bindings.
- Harness trap: referencing foo.e/which in the same top-level form as (require 'foo.e) fails at compile time (No such namespace); drivers must resolve at runtime ((ns-resolve 'foo.e 'which)) or split the forms. This cost one round of A5/net9 runs.
- *compile-path* root value on ClojureCLR 1.12.6 is "." (JVM default is "classes"); `compile` with an absent *compile-path* dir raised no error on net8 because nothing is written there anyway.
- RT.load's DLL lookup name is the dotted relative path plus extension (`foo.e.cljc.dll`) at a load-path root; a nested `foo/e.cljc.dll` is never consulted (RT.cs:3593). GenContext.CreateGenContext also rewrites '/' to '.' in the assembly name (GenContext.cs:145-155), so compile output and loader agree.
- Reader-conditional allowance in Compiler.load is keyed solely on the 3rd argument (sourceName) ending in ".cljc" (Compiler.cs:2043-2047); the 2nd argument only appears in error messages and the 4th becomes *file* / :file metadata. The prior-art port passes (file file-path file-path file-name), which puts the bare file name into :file metadata.

This affects claim C8 and the interop reminders in plan/verify/README.org and 04.
- Combining enum flags needs enum-or, not bit-or: (bit-or BindingFlags/NonPublic BindingFlags/Static) yields an Int64 that fails with InvalidCastException when passed to Type.GetMembers.
- Design-level: CancellationTokenSource.Cancel is where the ControlledExecution abort happens and it blocks the caller until delivery (11 ms for a CPU loop, forever for Monitor.Wait/Sleep/native/finally-loop bodies). The nREPL interrupt op must trigger it from a throwaway thread; an undeliverable abort therefore costs two zombie threads, not one (R2).
- Three exception types reach the eval boundary depending on where the interrupt lands: ThreadInterruptedException (Interrupt in a wait, including with an abort pending), OperationCanceledException (ControlledExecution abort of managed code), and a wrapper such as clojure.lang.Compiler+CompilerException with ThreadAbortException as InnerException (abort inside a catch block that rethrows); inside the aborted body user code sees ThreadAbortException and cannot swallow it. The port's interrupted? predicate (prior art checks only ThreadInterruptedException via root-cause) must cover all three.
- ControlledExecution abort latency on a spinning Clojure loop was 16-18 ms after Cancel for every loop shape (bare loop/recur, eval'd loop, loop with calls, while true, lazy reduce), and Thread.Interrupt wakes a wait within ~1 ms; a loop inside a finally or catch block that never returns from a managed call is never aborted, and catch blocks defer the abort until they exit.
- While an abort is pending, Thread.ThreadState shows the AbortRequested flag (e.g. "Background, WaitSleepJoin, AbortRequested"), which is a free diagnostic for an interrupt that could not be delivered.
- Prior art's interrupt-stop (clr.tools.nrepl session.clj:181-199) calls Interrupt twice 5 s apart; with TH3's latch semantics the second call can fire at the abandoned thread's next wait, which is harmless only if the thread is really abandoned.
- Socket.Shutdown(Both) from the owning side makes a blocked Receive return 0 with no exception (TH4), a cleaner reader-loop exit than Dispose's SocketException(ConnectionAborted).
- ClojureCLR Clojure.Main cold start in the container is ~2.7 s wall (smoke.cljc), consistent with A10's expectation.
