#+TITLE: 2. Facts: ClojureCLR 1.12.6, .NET 8, tooling
#+OPTIONS: ^:nil toc:2 num:nil
#+DATE: 2026-10-11

Every fact the design relies on, verified on 2026-10-11 in the =nrepl-clr= container (ClojureCLR 1.12.6 from NuGet, .NET 8.0.31, Debian 12) and against the =clojure-clr= source at tag =clojure-1.12.6= (commit =8284d3bc=). The claim id links the row to its experiment in [[file:verify/claims.org][verify/claims.org]] and [[file:verify/results.org][verify/results.org]]; "status" is the final verdict after two independent skeptics where one was assigned. Linux only: Windows socket, console and TLS behaviour was not exercised.

* .NET 8 threading, IO, networking
| Fact | Why it matters | Claim | Status |
|---+---+---+---|
| =Thread.Interrupt= wakes =Sleep=, =Monitor.Wait=, =BlockingCollection.Take=, a contended =Monitor.Enter= (=locking=), =SemaphoreSlim.Wait=, =WaitHandle=, =Join= with =ThreadInterruptedException= within ~1 ms | interrupt of an idle session | TH1 | confirmed |
| A spinning thread does not notice =Interrupt=; the interrupt is latched (single flag, not a counter) and fires at the next wait, including =Thread.Sleep(0)=; catching it consumes it | cooperative interrupt limits; re-latch inside the stdin proxy | TH2, TH3 | confirmed |
| =Interrupt= never unblocks =Socket.Receive= / =NetworkStream.Read=; =Socket.Dispose= / =Close= makes the blocked call throw =SocketException(ConnectionAborted)= (wrapped in =IOException= for =NetworkStream=); =Socket.Shutdown(Both)= or a peer close makes it return 0; =NetworkStream.Dispose(ownsSocket)= also returns 0 | transport reader shutdown | TH4, F6 | confirmed |
| =Thread.Abort= / =Suspend= / =Resume= / =ResetAbort= throw =PlatformNotSupportedException= | no JVM-style stop | TH5 | confirmed |
| =ControlledExecution.Run= aborts a Clojure =(loop [] (recur))= (bare, eval'd, =while=, lazy =reduce=) 16–18 ms after =Cancel=; =finally= blocks run; the runtime keeps working; =Run= surfaces =OperationCanceledException=; inside the body user code sees =ThreadAbortException=, which a =catch Exception= handler receives but cannot swallow; an abort landing inside the compiler surfaces =Compiler+CompilerException= with the abort as =InnerException= | =stop-exception?= walks the cause chain | TH6 | partial (the register expected =ThreadInterruptedException=) |
| =Cancel= blocks the caller until the abort is delivered; delivery is impossible while the thread is in a wait or a native call (=Interrupt= still wakes it), is deferred while inside a =catch= block, and never happens inside a loop that stays in a =catch= / =finally=; =ThreadState= shows =AbortRequested= meanwhile | the reaper re-interrupts, runs on its own thread, and R2 names the holes | TH7 | partial (the plan said =finally= blocks cannot be aborted) |
| =System.Threading.Timer= callbacks run on pool threads and overlap; a one-shot timer referenced only from its callback can be collected | the CLR reaper is a dedicated thread | TH11 | confirmed |
| =ThreadState= is a flags enum; =IsAlive= is the liveness check; a finished thread reads =Stopped=; =Thread.Name= can be set repeatedly; the main thread's name is nil | thread naming | TH12 | partial (the plan said "set once") |
| An uncaught exception on any managed thread terminates the process (exit 139); =AppDomain.UnhandledException= is observe-only | catch-all on every thread | TH13 | confirmed |
| =Thread= needs =(gen-delegate ThreadStart [] …)=; a Clojure fn or =sys-action= is rejected; =(Thread. d (int max-stack))= honours the stack size; default secondary stack on Linux is =ulimit -s= (8 MB) | =make-executor=, =session-thread= | C4, C5 | confirmed |
| =deftype= =^:unsynchronized-mutable= fields work; a =deftype= cannot extend an abstract class | =PushbackInputStream= is reused instead of a deftype | C6 | confirmed |
| =Monitor.Wait(o, ms)= returns false on timeout; =Pulse= must run inside the lock | rendezvous | C7 | confirmed |
| =BlockingCollection<Object>(1)=: =Add= / =Take= / =TryTake(by-ref, ms)= work; =by-ref= needs a statically resolved call with an untyped nil local (object out) or an exactly typed local (value out), outside a non-tail =try=; ms above =Int32.MaxValue= throws at the call site; =System.Threading.Timeout/Infinite= (-1) works | =poll!= wrapper shape | C8, TH extra, F extra | partial |
| =Task.Run= works with =sys-action= / =sys-func= and runs on the pool | not used by the design | C9 | confirmed |
| =Environment/Exit= terminates even with foreground threads alive; =AppDomain.ProcessExit= handlers run on a non-main thread; =Console.CancelKeyPress= works unless SIGINT is inherited as ignored (background child of a non-interactive shell) | process seam | C11 | confirmed |
| =proxy= dispatches by method name: every overload of a name shares one multi-arity fn; two clauses with one name fail ("Method redefined"); value-returning overrides must return the exact CLR type (=(int …)=); =^Char= parameter hints are rejected; =get_Encoding= is needed only when =.Encoding= is read; =proxy-super= unmaps the whole name during the call; the generated =Span= overloads throw =InvalidProgramException= when called | stdin and writer proxies | C1, C2 | partial |
| Proxy =TextWriter= =Write(char)= costs ~15 ns steady state (~85 ns cold), =StringWriter= ~3 ns, a C# subclass ~4 ns | D5 stays =proxy= | C3 | confirmed |
| =TextWriter.Dispose(bool)= and =Close= are reachable from a proxy and run before an enclosing =catch=; =WriteLine(string)= arrives as =Write(string)= + =Write(newline)= | quota ordering | E10 | confirmed |
| =Stream.Read(buf,0,n)= returns 0 at EOF, =ReadByte= -1; a =^|System.Byte[]|= (or =^bytes=) hint resolves the 3-arg overloads; =NetworkStream.Read(buf,0,0)= blocks until data is pending; =PushbackInputStream= over a bare =NetworkStream= blocks on =ReadByte= after =Unread=, over a =BufferedStream= it does not | bencode primitives | E1, E4 | confirmed / partial |
